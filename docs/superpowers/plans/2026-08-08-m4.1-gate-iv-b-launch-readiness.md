## Frozen interfaces

### Claim builder

`build_m4_1_launch_claim.py` accepts mutually exclusive `--check` and `--consume`. With no argument it behaves as `--check`, prints one deterministic compact JSON object, performs no network call, and writes nothing. `--consume` first revalidates the fixed IV-B review, live authorization remote ref, absence of every claim/result/terminal path, authorization auditor `READY_UNCONSUMED`, execution auditor `READY_UNCLAIMED`, and the exact protocol bindings. It then exclusively creates the sole Gate IV-A claim shape with 60 deterministic task/context/finalization bindings.

The only file-write primitive is:

```python
def exclusive_create_bytes(path: Path, raw: bytes) -> None:
    descriptor = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
    try:
        with os.fdopen(descriptor, "wb") as stream:
            descriptor = -1
            stream.write(raw)
            stream.flush()
            os.fsync(stream.fileno())
    finally:
        if descriptor >= 0:
            os.close(descriptor)
```

No error handler removes or replaces a path.

### Evidence recorder

`record_m4_1_execution_evidence.py` also defaults to `--check`. Explicit `--consume` supports three closed operations:

- `dispatch`: require the next task in the frozen prefix; exclusively create its result and platform-observation directories; preserve the supplied create-thread response bytes; validate one ready `threadId`/`hostId`; validate an exposed resolved checkout SHA; exclusively create the Gate IV-A receipt and response attestation.
- `final`: require the same task's valid receipt and no existing final; exclusively preserve the supplied `raw-final.txt`; run protocol validation without judging quality; return continue only for schema-valid results and otherwise require a stopped terminal.
- `terminal`: exclusively create exactly one Gate IV-A terminal. `COMPLETE_UNJUDGED` requires all 60 tasks; stopped requires the frozen prefix, failure stage/error evidence, later batches not started, and successor revision required.

The observation root is `evals/m4/execution/m4.1/platform-observations/<task-id>/`. Each task contains only `create-thread-response.json` and `create-thread-response-attestation.json`. The attestation binds the raw response SHA-256, canonical JSON SHA-256, actual ready identifiers, whether a resolved checkout SHA was exposed, and exact validation against the authorization HEAD.

### Launch-readiness auditor

`audit_m4_1_launch_readiness.py` validates the fixed review key set and all exact constants, proves the authorization and protocol commits are ancestors, proves every Gate IV-A protocol path is blob-identical to `bb1b8a5...`, invokes both writer checks in memory, requires authorization `READY_UNCONSUMED`, requires execution `READY_UNCLAIMED`, and requires every real claim/result/terminal/observation path absent. Its successful compact result is:

```json
{"authorization_audit":"READY_UNCONSUMED","errors":[],"execution_audit":"READY_UNCLAIMED","launch_claim":"ABSENT","protocol_review":"PASSED","result_root":"ABSENT","status":"READY_FOR_ATOMIC_CLAIM","token":"UNCONSUMED","writer_check":"DETERMINISTIC"}
```

It never consumes, writes, launches, judges, or aggregates.
