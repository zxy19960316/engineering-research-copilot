# M4.1 Successor Preparation and One-Shot Authorization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish M4.1 as a new, offline-only successor revision that fixes the PowerShell 5.1 request-hash preflight, freezes 60 new task identities without changing the evaluation matrix, passes exact-HEAD CI, and then receives a separately reviewed, unconsumed one-shot Gate IV authorization.

**Architecture:** Preserve M4.0 claim and failure evidence byte-for-byte. Add a versioned M4.1 preparation manifest plus a tracked read-only PowerShell preflight whose request bindings are generated and independently audited before authorization. After the preparation HEAD is green, create a distinct authorization branch and versioned review/authorization/control artifacts that bind the green preparation HEAD, current configured model defaults, the tracked helper, a new token, and the new roster. Stop with the token unconsumed and no launch claim, result root, fresh context, or finalization.

**Tech Stack:** Python 3.13 standard library, Windows PowerShell 5.1 and PowerShell 7, closed JSON contracts, `unittest`, Git full-history/blob audits, GitHub Actions, UTF-8/LF.

```powershell
function Get-BytesSha256([byte[]]$Bytes) {
    $sha = [System.Security.Cryptography.SHA256]::Create()
    try {
        return ([System.BitConverter]::ToString(
            $sha.ComputeHash($Bytes)
        )).Replace('-', '').ToLowerInvariant()
    }
    finally {
        $sha.Dispose()
    }
}
```
