# M4.2 One-Shot Authorization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deterministically issue exactly one unconsumed M4.2 authorization/control pair after candidate exact-head CI acceptance, without creating a claim, task context, dispatch, result, judge call, aggregate, or M4 closure.

**Architecture:** Build candidate bytes from immutable Git objects rooted at preparation closure HEAD `4efa75c542172a95c6c72c8c1450fea77a8e2ff1`; keep those bytes in memory during candidate validation. A separate auditor independently reconstructs every binding and recognizes exactly two legal states: candidate-ready/not-issued and authorized/unconsumed/not-claimed/not-executed. Publish one candidate commit and require both push and stacked Draft-PR CI to pass at that exact HEAD before performing one atomic write-once issuance and one closure commit.

**Tech Stack:** Python 3.13 standard library, JSON Schema Draft 2020-12, `unittest`, Git object plumbing, GitHub Actions, Bash strict mode, PowerShell 7 on Ubuntu, Windows PowerShell 5.1, UTF-8/LF.

## Interfaces

- `build_artifacts() -> dict[Path, bytes]` returns exactly the authorization and control target paths and performs no writes, network calls, Codex calls, or result-root reads.
- `authorization_token(payload: Mapping[str, object]) -> str` returns `sha256:` plus SHA-256 over compact, sorted, UTF-8 canonical bytes after removing `authorization_token`.
- `audit_authorization(repo_root: Path = REPO_ROOT, *, authorization_data: Mapping[str, object] | None = None, control_data: Mapping[str, object] | None = None, verify_git: bool = True, present_paths: set[str] | None = None) -> dict[str, object]` independently recomputes every binding without importing the builder.
- `--dry-run` prints only state, paths, byte lengths, raw hashes, and a truncated token fingerprint.
- `--check` requires both on-disk instances to be byte-identical to reconstruction.
- `--write-once --accepted-candidate-head <SHA>` requires exact HEAD, clean tree, absent targets/claim/execution/results, and atomically publishes both files or neither.
