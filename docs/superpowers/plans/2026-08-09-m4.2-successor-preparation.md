> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish M4.2 as a deterministic, offline-only successor preparation that preserves the stopped M4.1 evidence, freezes 60 new identities and request bindings, and stops at `M4_2_PREPARED_NOT_AUTHORIZED` without creating any authorization, claim, execution, or result artifact.

**Architecture:** Treat the raw M4.1 terminal evidence commit and the green terminal-closure commit as separate trust roots. Project the frozen M4.1 roster into disjoint M4.2 task, batch, blind, and future result identities, then validate the generated manifest with an independent read-only auditor and a PowerShell 5.1/7-compatible request preflight. Keep the lifecycle repair requirement explicit: any future post-claim confirmation must be claim-aware and must not rerun claim-absence gates.

**Tech Stack:** Python 3.13 standard library, Windows PowerShell 5.1, PowerShell 7, closed JSON contracts, `unittest`, Git full-history/blob audits, GitHub Actions, UTF-8/LF.
