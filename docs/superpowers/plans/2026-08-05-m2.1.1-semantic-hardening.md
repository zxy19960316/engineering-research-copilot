# M2.1.1 Semantic Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the offline M2 direction-decision contract from `m2.1` to `m2.1.1` so confirmation, direction semantics, route provenance, evidence policy, data preconditions, direction axes, and scorecards are structurally auditable.

**Architecture:** Keep the installable Skill thin and implement the closed contract in the existing standard-library validator. Bind every state transition with canonical SHA-256 values, derive semantic relationships from closed identifiers and profiles rather than title keywords, and preserve all test/evaluation artifacts outside the Skill package. Treat all validation as offline contract evidence only.

**Tech Stack:** Markdown, JSON, Python standard library, `unittest`, canonical UTF-8 JSON SHA-256, GitHub Actions.

## Global Constraints

- Execute only M2.1.1 semantic hardening; keep M3 `NOT_STARTED`.
- Preserve all accepted M1 evidence and metadata byte-for-byte.
- Do not execute experiments, simulations, training, downloads, deployment, RRC, services, or platform integration.
- Require closed objects and reject unknown fields throughout the M2.1.1 schema.
- Canonicalize with UTF-8, `sort_keys=True`, compact separators, `ensure_ascii=False`, and rejected non-finite numbers.
- Keep CLI exit codes `valid=0`, `invalid=1`, and `evidence_incomplete=2`.
- Keep offline fixture validation distinct from real citation verification, empirical success, identity proof, and nuclear-safety validation.
- Use TDD, preserve failing evidence, commit bounded phases, stage explicit paths, and do not push or merge without explicit authorization.
