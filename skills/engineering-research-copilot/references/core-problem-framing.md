# 问题界定与纠偏

当研究者只有模糊概念、跨学科直觉、范围过大的候选选题，或前提可能有误时，应用本协议。在检索文献或设计路线前，先给出有用的澄清结果。

## 从预期决策开始

复述研究者似乎准备解释、预测、设计、比较或决定什么。把工程对象与拟用方法分开：方法名不是研究问题，宽泛应用领域也不是可证伪选题。

先给出暂定解释和影响最大的歧义。尽量一次只问一个判别问题，一次回复绝不超过三个问题。提供具体解释供用户选择，不要求用户先发明回答所需的专业词汇。

## 先诊断，再纠正

把实质问题归入以下一种或多种类型：

- **术语错误**——术语用法与相关领域的含义冲突；
- **事实冲突**——前提与可靠的当前证据或用户材料冲突；
- **范畴或因果错误**——混淆不同量、机制、层级、相关关系和因果关系；
- **无支持假设**——前提可能合理，但当前没有确立的支持；
- **规格缺失**——缺少研究总体、系统边界、工况、比较对象、结果指标或资源约束；
- **范围或可行性错配**——拟议贡献无法用现有权限、时间、数据或工具检验；
- **一般歧义**——仍有多个可行解释，且无法判定其中任何一个错误。

不要仅因缺少直接先例，就把陌生或非常规想法判为错误。当纠偏依赖当前外部事实或专业定义时，先核验相关事实；无法核验时，说明疑点以及哪类来源可以裁决。

## 让每次纠偏都可逆

任何会改变研究方向的问题，都给出紧凑的纠偏记录：

| 字段 | 内容 |
|---|---|
| **原始概念** | 保留研究者原话或忠实的简短复述。 |
| **问题类型** | 指明错误、冲突、假设、歧义或可行性问题。 |
| **建议修正** | 给出最小且科学上可辩护的改动。 |
| **证据边界** | 说明修正已核验、来自用户、属于推断，还是仍未解决。 |
| **影响** | 说明修正会怎样改变选题、检索、方法或主张。 |
| **用户选择** | 对重要重构记录接受、拒绝、修改或未决定。 |

不要静默替换研究者的目标。对影响很小且显然的术语错误，可以在解释后直接修正；如果会改变科学问题、预期贡献或项目边界，先请用户选择。

## 构建选题框架

逐步收敛到以下组成部分，并让未知项保持可见：

- **工程对象**——系统、过程、部件、总体、信号或决策场景；
- **缺口或机制**——待研究的故障、未知关系、局限或因果机制；
- **干预或解释因素**——方法、设计变更、暴露、参数、表征或比较；
- **结果指标**——可观测响应、性能、不确定度、可靠性、安全性或解释目标；
- **运行边界**——工况、尺度、环境、总体、时间范围和排除项；
- **证据需求**——直接问题证据、方法先例、迁移桥接、反证或验证数据；
- **可行性约束**——数据、设备、仿真器、软件、算力、专业能力、时间、预算、安全和访问权限；
- **可证伪研究问题**——存在某种可能观察结果能够反驳拟议答案的问题。

区分选题、研究问题、假设和方法。不要通过换一种说法制造创新性；在有边界且经过核验的文献检索完成前，把创新性标为暂定。

## 返回与就绪度匹配的界定结果

选择最深且真实的结果：

- **解释集合**：两到三个可信解释，以及区分它们的问题；
- **纠正后的问题框架**：当前问题、纠偏记录、假设和下一步证据需求；
- **候选选题组合**：一个聚焦选题，以及必要时的相邻选项和高风险选项；
- **研究问题简报**：可证伪问题、范围、可行性边界、暂定贡献和检索计划。

最后给出信息增益最大的下一项检查：澄清、事实核验、范围检索、可行性探查或用户选题。问题仍有实质歧义时，不要生成完整研究路线。
