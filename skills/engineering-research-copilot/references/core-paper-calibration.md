# 论文校准

在发现、核验、比较或重新组织文献时应用本文件。把文献检索视为证据校准，而不是把搜索结果直接当作事实或推荐。

## 从当前材料建立简报

先提取并展示一份紧凑研究简报：

- 当前问题、对象、场景和预期用途；
- 需要支持、反驳或限定的主张；
- 已知约束、排除项、时间范围和领域边界；
- 用户提供的文献、笔记或判断及其当前核验状态；
- 会改变检索或选择结果的实质未知项。

不要因输入模糊就只返回问卷。先给出可用的问题解释或有限候选框架，再询问最多三个会实质改变下一轮结果的问题。

## 分开发现、身份核验和内容核验

对每条候选文献依次记录三个相互独立的状态：

1. **发现状态**：记录检索来源、查询、筛选原因和原始定位信息。发现记录只说明“看到了一个候选”。
2. **身份状态**：用出版商、注册机构、可信索引或作者版本核对题名、作者、年份、载体、版本和标识符。字段冲突未解决前不得进入推荐池。
3. **内容状态**：说明实际检查了元数据、摘要、全文还是用户摘录，并把每个判断限制在可见内容内。

不得根据搜索摘要、文件名、相似题名或调用方标签推断 DOI、作者列表、发表状态或版本关系。发现服务的流行度、被引次数和排序只能作为发现信号，不能替代身份或内容核验。

## 标明证据层级

为每项实质判断标注一个主要依据：

- `discovery_only`：仅有发现记录，不支持内容主张；
- `metadata_level`：只支持身份、年份、载体等书目信息；
- `abstract_level`：只支持摘要明确陈述的范围；
- `full_text_level`：支持已检查正文、方法、结果、图表或补充材料中的具体判断；
- `user_material`：来自用户材料，保留来源位置并明确尚未独立核验的部分；
- `explicit_hypothesis`：属于待检验推断，不伪装成文献结论。

边和综合结论的层级不得高于其最弱必要来源。无法确认依据时降级或阻断，不要补全缺失内容。

## 维护候选台账

每条候选至少保留：稳定本地 ID、身份字段、来源定位、核验状态、证据层级、与问题的关系、支持角色、局限或反证、访问限制和推荐资格。

使用以下推荐资格：

- `eligible`：身份无冲突，内容层级足以支持当前用途；
- `exploration_only`：可用于方法发现或迁移探索，但不足以支撑主方向或安全结论；
- `blocked`：身份冲突、内容不可见、关键字段缺失或证据与主张不匹配；
- `rejected`：与当前问题不符，保留拒绝原因以防重复检索。

已核验预印本可支持方法或探索，但不能作为主方向或安全相关结论的唯一证据。不要删除负面结果、局限论文或失败分支。

## 迭代校准

先完成一轮有界候选发现、核验和角色分配，再让用户针对方向、范围、排除项或资源约束给出反馈。反馈改变问题时：

1. 显示继承、拒绝、重置和新增约束；
2. 记录查询、筛选和证据角色的差异；
3. 只重新处理受影响部分；
4. 保留先前候选及其状态，不把旧判断静默改写为新判断。

不强制固定轮数。证据已经足够时停止扩张；新增检索不再改变关键判断时说明收益递减；缺口无法在当前权限和来源内解决时诚实结束本次尝试。

## 返回真实就绪度

只使用与实际证据一致的状态：

- `ready_for_current_use`：关键身份已核验，证据层级足以完成用户当前用途，冲突和局限可见；
- `evidence_incomplete`：已有阶段性结果，但一个或多个缺口会改变结论或下一行动；
- `citation_conflict`：关键身份或版本冲突尚未解决，受影响记录不得推荐；
- `needs_user_decision`：存在多个可辩护边界，必须由用户选择范围、排除项或证据成本。

就绪仅针对声明的当前用途。可用于概念理解不等于可用于方向确认、正式路线、安全判断或论文主张。

## 交付可追溯结果

返回以下内容，并按任务复杂度压缩呈现：

- 研究简报及约束变化；
- 可推荐、探索、阻断和拒绝候选的分组台账；
- 每个关键观点的来源 ID 与证据层级；
- 支持、局限、反证和未解决冲突；
- 从同一结构化记录生成的证据图和文本回退；
- 当前就绪度、实质缺口和下一项最小行动。

在本阶段停止于文献与证据基础。不要据此自动确认方向、生成完整实验或仿真路线、运行分析、下载材料或写入用户文件。
