# 研究路线规划

当研究者要求实验、仿真、建模、数据分析或最小判别路线时，应用本协议。让输出匹配当前就绪度；一份有编号的详细计划并不会因此自动成为可执行路线。

## 目录

- 判定路线就绪度
- 闭合可执行前提
- 构建研究闭环
- 处理数据与机器学习路线
- 向研究者呈现路线
- 生成正式路线制品
- 保持执行边界

## 判定路线就绪度

在对话模式中，只返回一个真实层级：

| 层级 | 适用条件 | 交付内容 |
|---|---|---|
| **概念草图** | 方向尚未确认、证据仍属暂定，或用户正在探索机制。 | 说明假设、可信研究逻辑、主要替代项，以及下一步所需证据或决策；避免给出完整操作程序。 |
| **路线准备方案** | 方向已确认，但仍有重要证据、数据、资源、访问、阈值或有效性条件未解决。 | 展示拟议设计、未决条件、有界预检，以及路线升级或被否决的标准。 |
| **可执行路线** | 方向已经明确确认，所有阻断输入均充分解决，每个决策阈值都有来源，而且用户明确要求生成完整路线。 | 在所有资源和权限限制内，给出下述完整研究闭环。 |

使用所有已知条件都支持的最高层级。任一阻断条件未解决时，下调标签；仍保留设计中有用部分，不要只返回停止码。

## 闭合可执行前提

标为可执行路线前，确认以下全部条件：

- 研究者明确选择了方向，且此后没有改变实质约束；
- 合格证据支持目标问题以及路线的关键机制或迁移假设；
- 所需数据集、设备、仿真器、软件依赖和专家输入均已具备，或有范围明确的获取检查；
- 明确采样单元、目标、预测变量、对照、混杂因素和预期主张；
- 主指标有单位和决策规则；
- 每个数值化成功、停止或转向阈值都说明责任主体和来源：用户指定、来源推导、标准推导或先导试验估计；
- 时间、算力、设备、人员和安全限制符合声明的资源边界；
- 用户已经要求生成路线。讨论路线的权限不等于执行路线的权限。

没有责任主体或可信推导的阈值仍属未解决。建议用先导试验或敏感性分析确定它，不要虚构方便的数字。

## 构建研究闭环

可执行路线必须覆盖以下全部内容。路线准备方案则填写已有支持的内容，把其他内容标为就绪工作。

### 可证伪假设

陈述一个可能被观察结果反驳的主张。区分工程主张与机制或迁移假设，并指出足以反驳它的最小结果。

### 基线与对照

选择最简单可信的现行方案、消融方案或零假设比较对象。设计允许时，说明阳性和阴性对照，并解释每个比较隔离了什么。

### 输入与输出

列出采样单元、输入、目标、输出、控制变量、混杂因素、单位、覆盖范围和来源。明确区分用户提供事实、已核验事实和未解决假设。

### 有序步骤

把工作拆成若干阶段，每阶段包含动作、所需输入、可观察输出、验收检查和停止条件。从成本最低且最能判别的检查开始，让后续阶段依赖前序证据，而不是把所有分支都写成必做工作。

### 指标与阈值

指定一个主指标，并只保留有用的次指标。对每个决策指标说明单位、评估总体、聚合规则、适用时的不确定区间，以及带来源的成功、停止或转向标准。

### 不确定性、敏感性与有效性

处理测量或数值不确定性、对重要假设的敏感性、内部有效性、外部或迁移有效性以及可复现性。区分仿真验证与确认，也区分预测质量与不确定性校准。

### 推进、停止与转向

让每个条件都可观察，并绑定到指标或预检结果。推进条件只授权下一项有界阶段；停止条件防止无支持延续；转向条件说明结果将触发哪种替代设计或问题。

### 证据—主张链

追踪“设计 → 数据 → 处理 → 分析 → 结果 → 解释 → 主张”。对每项主要主张，指出支持它的结果、指标、来源或观察及其局限；把无支持的外延排除在贡献之外。

## 处理数据与机器学习路线

除一般闭环外，明确以下内容：

- 稳定的样本和分组身份，包括重复观察与相关仿真；
- 训练、验证、校准和最终测试单元，并在需要时采用分组感知或时间感知划分；
- 预处理和表征拟合仅使用相应训练分区；
- 检查目标、未来信息、重复样本、仿真随机种子、场景族和特征构造造成的泄漏；
- 用基线区分表征价值与回归器或分类器复杂度；
- 声称概率或不确定性时，检查校准、覆盖率、选择性风险或分布外表现；
- 在预期部署偏移或外推偏移下评估；
- 保留从原始来源到派生特征、模型输出、指标和主张的精确血缘。

只有划分比例而没有划分单元和分组策略时，视为不完整。概率输出没有校准目标和评估规则时，只能称为分数，不能称为已验证的不确定性。

## 向研究者呈现路线

先说明路线层级和一句话理由，再展示拟议研究闭环、证据边界、未解决阻断项和最佳下一步。多个阶段字段相同时优先使用紧凑表格。对话模式不暴露正式标识符和哈希。

## 生成正式路线制品

仅在制品模式且方向已经有效确认后，使用以下闭合封装：

```yaml
selected_direction_id: "D1"
source_direction_hash: ""
confirmation_event_hash: ""
source_bundle_hash: ""
hypothesis: ""
baselines: []
controls: []
sequence: []
inputs: []
outputs: []
controlled_variables: []
confounders: []
primary_metrics: []
secondary_metrics: []
minimum_meaningful_improvement: ""
uncertainty_checks: []
sensitivity_checks: []
validity_checks: []
go_conditions: []
stop_conditions: []
pivot_conditions: []
route_traceability: []
source_test_mapping: []
inherited_constraints: []
approved_constraint_changes: []
evidence_chain:
  design: []
  data: []
  analysis: []
  result: []
  claim: []
```

所选方向必须与已确认决策一致。根据权威对象重新计算方向、确认事件和来源包哈希。要求数值条件结构化，并完整覆盖所选方向的全部主张和最小检验指标。逐字复制资源限制；只有旧值、新值、有限数值、单位、批准来源和批准消息哈希齐全时，才接受变更。只验证封装，不执行路线。

除 `approved_constraint_changes` 在没有获准变更时可为空列表外，其余封装字段均不得为空。拒绝复制路线、过期绑定、缺失主张映射和静默扩大资源。

## 保持执行边界

路线生成与路线执行是两项独立权限。把路线作为计划返回。只有用户另行明确请求，并重新检查安全、访问、成本和环境约束后，才启动实验、仿真、训练、下载、上传、服务、部署或大量资源使用。
